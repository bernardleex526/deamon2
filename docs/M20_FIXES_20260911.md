# M20 基础步态跟随修复（2026-09-11）

本文说明新的 `config/m20.yaml`。历史交接和回放报告仍然保留，不应把旧版本结论当成当前配置。此版本是待实机标定的跟随层，不取代 NOS 原厂导航，不代表真实跟随已经验收。

## 控制行为

- 初始选点：按现有融合/body 坐标假设，前雷达前方 1.5 米暂对应 `(1.82028, 0)`。这不是新完成的外参标定。
- 跟随距离：机身原点到选定点簇的平面距离 1.2 米；跟踪的是点簇，不是人体语义。
- `gait_aware_follow=true` 使用转向、接近、保持控制。默认不倒退、不主动横移，`linear.y=0`。
- 距离误差大于 0.10 米才重新接近，小于等于 0.06 米进入保持。这个滞回区避免在阈值附近频繁启停。
- 非零前进意图 0.22~0.30 m/s；转向意图绝对值 0.52~0.60 rad/s。转向启动/停止角度阈值分别为 0.15/0.07 rad。转向时不同时前进。
- 仅在明确超出位置/角度容差时请求步态有效速度。Guard 继续拒绝低于步态最小速度的请求，不把任意微小噪声放大为运动。
- 运动中增速受限；从零进入步态有效区以及停止仍是离散变化，必须在受控场地标定起步和制动，不宣称连续平滑或物理停车误差。
- `expected_gait=4097` 固定当前控制律的步态契约。步态改变会撤销 arm，不能直接继承旧许可。
- `gait_aware_follow=false` 保留此前最小修复的上游风格控制，用于历史对照；live launch 不接受该旧配置。

## 点簇关联与丢失

- 在选点窗口内按相邻点的空间间隔分簇，至少 3 个扫描点才构成候选。
- 比较候选簇与上一目标中心的距离；两个候选同样接近时判为歧义并停止，不平均成不存在的中间目标。
- 初次选择记录关联点数预算。点簇短暂合并时只用最靠近上一目标中心的预算内点更新，防止新增背景点把目标质心拉走。
- 空扫描、稀疏/丢失/歧义目标、无效坐标系、过期扫描会锁止计算并清零。
- 返回的点不会自动解除锁止。需要重新发布选点、确认有效关联，再使能跟随；桥还必须单独重新 arm。
- 发布前复审补充了 `/robot_nexus/select_target` 原子服务：请求携带坐标、坐标系、发送时间和从状态话题读到的 `fault_epoch`。故障会改变代次，故障前排队的请求因此被拒绝；不再依赖消息到达顺序推断发送时间。
- M20 配置不再订阅旧的无时间戳 `/robot_nexus/target` Point 话题，Web/Android/actions 也不允许作为该配置的无时间戳旁路。旧 Point 接口仅用于 legacy 配置。
- 使能服务检测到过期输入会立即锁止；新扫描刷新旧时间前也检查已过期的间隔。负秒值、越界纳秒先校验，再进入归零路径，不构造会抛异常的 ROS 时间对象。
- `/robot_nexus/enable_follow` 使能请求也携带选择代次、故障代次和发送时间，故障前的排队使能不能启用故障后重新选择的目标。`set_moving(false)` 始终可用，并使已排队的使能请求失效；M20 不再接受 `set_moving(true)`。
- 几何关联不能保证所有交叉、遮挡、静态背景场景都不换目标。实物遮挡验收不能用合成数据替代。

## APF 与保护

- M20 APF 改为相对机身矩形外缘的净空：作用距离 0.60 米、减速距离 0.40 米、紧急距离 0.12 米，不再把作用圆完全放进自体排除区。
- APF/走廊提供有限转向偏置；近障限制前进速度预算。预算低于最小有效步态速度时停止，不重新抬速。
- 外层完整停止区不变：前后 0.70 米、半宽 0.40 米，不过滤后方保护点。
- 这些几何参数仍需结合实际机身、腿部扫掠范围和刹车距离验证，不是完整碰撞安全认证。

## 时效与桥接契约

- 新接口 `/robot_nexus/tracking_status` 提供选择代次、故障代次、有效性、状态、目标中心/点数、走廊/APF 项及采集时间戳。
- M20 的扫描和跟踪状态采集到使用期限统一为 0.5 秒，沿用既有传感器新鲜度上限。已消耗的网络延迟从预算扣除，接收消息不会重新增加一段有效期。
- 命令超时仍为 0.3 秒；BasicStatus 超时仍为 1.5 秒。时间到期或无效输入解除 arm，恢复输入不会自动 arm。
- live Bridge 自身也强制要求 commissioning、目标状态门控、基础步态契约和非仿真时钟，不依赖 launch 单独检查。
- 桥接配置及 M20 节点参数运行时不接受修改，包括 `use_sim_time`；改配置后必须重启。选择/使能通过现有话题和服务执行。
- `dry_run=true` 不创建 AOS UDP 客户端。模拟测试中的 arm 仅限独立 Domain、localhost-only 的测试实例。

此前 GOS 工作区 `/home/user/m20_fixed_20260911` 是新选点服务之前的快照。GitHub 发布不会自动升级机器人安装。当前操作示例使用全新 `/home/user/m20_release_ws`，须先按 README 克隆当前源码并编译；旧工作区保留用于比较，不覆盖原厂软件。

先确认没有已有实例，再运行以下 dry-run；凭据只在终端输入，不写入脚本或文档。

```bash

```

另一个同环境终端先选点，再查看状态：

```bash
ros2 run jie_deamon m20_select_target.py 1.82028 0 --frame lidar_link
ros2 topic echo /robot_nexus/tracking_status std_msgs/msg/String
```

只有持续 `tracking_valid=true` 且目标确实是所选点簇时才开启计算预览：

```bash
ros2 run jie_deamon m20_enable_follow.py
# 结束计算预览
ros2 service call /robot_nexus/set_moving std_srvs/srv/SetBool '{data: false}'
```

选点工具只读取故障代次并发送一次带时间戳的请求，不使能、不 arm，也不移动机器人。返回 accepted 仅说明请求被接收，还需检查 tracking_valid。关闭 launch 后目标选择不保留。出现 `lost`、`ambiguous_target` 或 `scan_stale` 时，先检查原因，再重新选点；不要循环自动重新使能。

服务复用 `rcl_interfaces/srv/SetParametersAtomically`，但不会修改节点参数。六个字段是 double `target_x/target_y`、string `frame_id`、integer `stamp_sec/stamp_nanosec/fault_epoch`。不要手工猜测代次；使用上述工具从服务器当前状态读取。
使能服务复用同一类型，四个字段均为 integer：`selection_id/fault_epoch/stamp_sec/stamp_nanosec`。使能工具只发送一次请求，不 arm；如果 live 桥已经另行 arm，则使能后的算法意图可能执行，必须遵守实机授权边界。
